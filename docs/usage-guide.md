# DSH Usage 使用指南

本指南介绍 `@rongyi7/dsh-stats`（界面品牌 **DSH Usage**）的安装、四个页面、计价规则、
账户查询、数据来源与导出。入门介绍见 [README](../README.md)，架构与数据契约见
[DESIGN.md](../DESIGN.md)。

- 适用版本：主分支 `0.5.0`。npm 上的稳定版是 `0.4.3`，部分界面细节以实际安装版本为准。
- 支持环境：DSH 桌面端、DSH Web 宿主。

## 1. 安装

插件安装到 DSH 的 **profile**。桌面端和 Web 是两个 profile（`desktop`、`web`），
装到其中一个不会同时装到另一个。

插件本身要求 Node.js 22 或更高。桌面端自带运行时（当前为 Node 24），不需要另外安装 Node；
Web 宿主按 DSH 自身的要求准备 Node。

命令里的 `-w` 是 pnpm 的 workspace 安装选项，表示在这个 profile 目录（workspace root）里安装，
不是文件路径。

### 1.1 桌面端

`desktop` profile 由桌面应用自己管理，请使用应用自带的 CLI。另行用 npm 安装的 `dsh` 会拒绝
操作这个 profile：

```text
error: profile "desktop" is managed exclusively by the Electron application
```

macOS 下自带 CLI 的路径和命令：

```bash
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" plugin \
  --profile desktop add -w @rongyi7/dsh-stats
```

安装完成后**完整退出 DSH**（macOS 用 Cmd+Q，而不是只关窗口），再重新打开。
侧边栏底部的「用量」就是入口。

不要手工改 `~/.dsh/profiles/desktop` 下的文件：profile 的依赖、bundle 注册和补丁层由应用维护。

### 1.2 Web

```bash
dsh plugin --profile web add -w @rongyi7/dsh-stats
```

然后重启 Web 宿主：

```bash
dsh web
```

刷新页面后，侧边栏底部出现「用量」。只刷新浏览器不会重新加载宿主侧插件。

### 1.3 自定义 profile

使用实际的 profile 名称替换 `desktop` / `web`：

```bash
dsh plugin --profile <name> add -w @rongyi7/dsh-stats
```

### 1.4 固定版本与本地 tarball

固定到已发布的版本（示例为当前稳定版）：

```bash
dsh plugin --profile web add -w @rongyi7/dsh-stats@0.4.3
```

安装本地构建的 tarball（`npm pack` 生成）。桌面端同样使用自带 CLI：

```bash
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" plugin \
  --profile desktop add -w ./rongyi7-dsh-stats-0.5.0.tgz
```

上面的文件名随版本变化。桌面端安装时，把 §1.1 命令里的包名换成 tarball 路径即可。
`0.5.0` 尚未发布到 npm，因此不能用 `@0.5.0` 作为可从 npm 下载的示例；本地 tarball 只用于
自己构建或验证。

### 1.5 确认是否注册成功

Web：

```bash
dsh --profile web --dump-config
```

输出里应能看到 `stats` 和 `@rongyi7/dsh-stats`。这个命令会重新生成该 profile 的 `cordis.yml`。

桌面端不能用 `--dump-config`：这个命令对 `desktop` profile 一律拒绝，即使用自带 CLI 也一样。
可以打开 `~/.dsh/profiles/desktop/package.json`，确认 `dependencies` 和 `dsh.profile.bundles` 里
都包含 `@rongyi7/dsh-stats`；或者直接看侧边栏底部有没有「用量」。

### 1.6 升级与卸载

升级就是重新执行安装命令并指定目标版本，然后按 1.1 / 1.2 的方式重启：

```bash
dsh plugin --profile web add -w @rongyi7/dsh-stats@latest
```

卸载：

```bash
dsh plugin --profile web remove @rongyi7/dsh-stats
```

卸载后同样需要重启宿主。

### 1.7 常见安装报错

| 现象 | 处理 |
| --- | --- |
| pnpm 报 `ERR_PNPM_ADDING_TO_ROOT` | 命令加上 `-w`，因为 profile 目录就是 workspace root。 |
| 装完侧边栏没有「用量」 | 确认命令成功、完整重启宿主；浏览器再做一次硬刷新。DSH 会缓存客户端模块和 Typert 描述符。 |
| 桌面端重启后仍无入口 | 确认装的是 `desktop` profile，而不是只装了 `web`。 |
| 用 `npm install --prefix ~/.dsh/profiles/web ...` 直接改 profile | 不要这样做。profile 由 pnpm 管理，官方 `dsh plugin` 命令会同时处理依赖和 bundle 注册。 |
| 价格页提示“计价设置暂不可用，请确认插件版本” | 宿主侧没有加载到当前插件版本，重启宿主。Web 仍失败时检查 `dsh --profile web --dump-config`；桌面端改看侧边栏入口或 §1.5 的 profile 文件。 |

### 1.8 版本与兼容性

| 项目 | 当前状态（2026-10-21 核对） |
| --- | --- |
| npm 稳定版 | `0.4.3`，2026-10-15 发布 |
| 本仓库主分支 | `0.5.0`，尚未发布 |
| 桌面版内置 Harness | `0.2.1-rc.2` |
| 插件 `0.5.0` 的声明 | `engines.dsh: >=0.1.0-rc.6 <0.3.0`，另有 peer 范围 |
| 插件 `0.4.3` 的声明 | 无 `engines.dsh`；peer 范围写到 `^0.2.0-rc.2` |

宿主加载插件前会检查兼容性：有 `engines.dsh` 时只看它，没有才逐条检查 `@deepseek-ai/dsh*`
的 peer 范围，并且两者都允许预发布版本参与（`includePrerelease`）。因此：

- `0.5.0` 的 `engines.dsh` 覆盖 `0.2.1-rc.2`，可以直接加载。
- `0.4.3` 没有 `engines.dsh`，peer 范围虽然只写到 `^0.2.0-rc.2`，但预发布版本参与比较，
  `0.2.1-rc.2` 仍落在范围内，所以也会被**允许加载**。

允许加载不等于验收通过。`0.4.3` 的验证覆盖到 `0.2.0-rc.2`（模块契约与浏览器夹具）；
在 `0.2.1-rc.2` 上完成完整 Web 验证的是 `0.5.0`。在 `0.5.0` 发布前，桌面端装 npm 稳定版可以
加载，但属于未验收组合。

逐版本的真机、模块契约与浏览器夹具结果见 [兼容性矩阵](compatibility.md)。
“支持桌面端”指当前版本在桌面端可用，不代表所有历史版本和所有操作系统都做过真机验收。

## 2. 四个页面

面板顶部有四个标签页：项目总览、开发时间线、用量趋势、账户余额。头部固定显示当前数据来源
状态点、刷新、导出、计价设置（齿轮）和关闭。

### 2.1 项目总览

- 顶部是预估费用、Token 构成、会话数与 LLM 时长，下面是活跃时段、活跃日、首 token 均值、
  输出速度等指标。
- 项目表可按任意列排序，表头吸顶；展开一行可以看该项目的轮/步、工具时长、首 token、
  tok/s 和会话明细。
- 右上角「筛选项目」可以搜索项目或路径，并隐藏不想看的项目。隐藏的项目不计入指标、表格和趋势页。
- 项目每页 50 个、会话每页 100 条；翻页不改变顶部汇总。
- 项目总览、开发时间线、用量趋势共用“筛选项目”，账户余额不受影响。

### 2.2 开发时间线

- **按日**：项目排成泳道，上方每根柱子是一个半小时的费用或 Token；点色条或柱子查看这半小时
  的明细，展开泳道可以打开会话。
- **全部**：日历矩阵，每页 30 天，点格子进入当天。
- 柱图指标可在费用和 Token 之间切换，着色可按强度或项目。
- 同一项目的并发会话在时间线里合并为墙钟区间；项目的 LLM/工具时长仍是累计工作量指标。

### 2.3 用量趋势

- 范围可选近 7 / 30 / 90 天，指标可在费用和 Token 之间切换。
- 上方摘要条给出区间合计、日均、活跃天数和最常用模型。
- 中间是每日柱图，虚线表示活跃日的日均。
- 下方是固定 26 周的活动热力图，颜色按活跃日的分位数分级；“当前连续”指一直连到今天或昨天的
  连续天数。
- 末尾按当前指标列出模型占比。点柱子或热力格会跳到那天的总览。
- LLM 时长按 Token 占比从会话分摊，是近似值。

### 2.4 账户余额

- 一屏列出所有已接入账户，按紧急程度排序：额度或余额快用完、凭证失效、快照过期的账户排在前面。
- 多账户时顶部摘要条按币种合计可用余额，并给出最紧的额度和需要关注的账户数。
- 每行显示余额构成，或每个订阅窗口的剩余额度条与重置时间（北京时间）。
- 可以给每个余额账户设一条提醒线。提醒只保存在当前浏览器，按该账户的原币种比较，不换算汇率。
- 单个账户刷新失败只影响它自己那一行，并标为「已过期」。
- 整次查询失败时：如果已有上次成功结果，标题状态变成「快照已过期」，内容上方出现可重试的横幅，
  账户行保持可见；如果还没有任何结果，标题显示「读取失败」，账户区显示「没有读到账户数据」
  并在那里提供重试，不再另出横幅。
- 账户页不提供导出，因为余额是实时快照，不属于历史统计。

## 3. 计价与费用

### 3.1 金额怎么算

- 所有价格按**每百万 Token** 计算，消费汇总统一换算为人民币（CNY），界面和消费导出只显示人民币。
- 当前使用固定汇率快照 `1 USD = 6.7205 CNY`，日期 `2026-08-26`，来源
  [Frankfurter](https://api.frankfurter.app/2026-08-26?from=USD&to=CNY)。
  汇率不会随实时行情浮动，旧统计也不会在每次打开面板时重新联网改写。
- 计价内核同时考虑上下文长度、服务档、缓存类型和生效时间。
- 账户余额页保留 Provider 原生币种，不做换算。
- 这是按公开价格推算的**估算**，不等于 Provider 账单。

### 3.2 界面上的三种金额

| 显示 | 含义 |
| --- | --- |
| `¥12.34` | 有可用价格，金额已计入汇总。 |
| `¥12.34*` | 部分用量可计价，另一部分无法安全计价；点开可看说明。 |
| 待计价 | 没有足够可靠的规则，该会话不计入费用合计。 |

费用旁的 ⓘ 提供说明。计价抽屉和会话详情里还会出现「费用含估算」「部分用量未计价」
「暂无可用价格」等标签。

### 3.3 消费状态

| 状态 | 含义 |
| --- | --- |
| `exact` | 每一条有价用量都命中确定的内置规则。 |
| `estimated` | 有金额，但至少一条记录来自动态价格快照、缺少会影响价格的元数据，或未知 API Provider 借用了唯一匹配或最长已知全称前缀匹配的官方模型价；界面显示计算后的人民币金额，估算状态保留在数据和导出字段中。 |
| `free` | 命中的用量全部免费；汇总保留零金额，不会误显示为未知消费。 |
| `partial` | 一部分用量可计价，另一部分无法安全计价；主汇总显示已计价 CNY 并加 `*`。 |
| `unsupported` | 没有足够可靠的规则；该会话不计入费用合计，界面显示「待计价」。 |

单条用量还可能标记为 `subscription`（订阅 / Token Plan）或 `ambiguous`（规则冲突）。
`coding-plan`、`coding_plan` 等订阅别名会在计价前统一归一化，绝不会伪装成 API 消费。

### 3.4 什么时候不猜价

- 显式 `relay`、`local` 且未配置自定义费率。
- 订阅 / Token Plan 用量：不折算成 API 费用。
- 未知模型，或模型名缺失。
- 多条规则冲突（`ambiguous`）。
- 未知 Provider 做回退匹配时，模型名多出来的那段后缀命中价格敏感词，例如 `-mini`、`-pro`、
  `-vision`、`:batch`、`:free`。这只限制“借用更短的已知模型价”；目录里本身有独立规则的模型
  （比如 `gpt-5.4-mini`）照常按自己的规则计价。

这些会话不进入主费用汇总。原因在会话详情和 RPC 的 `meta.warnings` 里；导出只保留
`costStatus`、`ruleId`、`pricingSource`，可以据此逐条定位。

### 3.5 Provider 匹配

- 计价优先按 **Provider-scoped** 规则处理：明确识别为官方 Provider 的请求命中官方价并标记为 `exact`。
- DSH 透传渠道 `nbdeepseek` 与 `deepseek-modlens` 明确沿用 DeepSeek 官方 API 计价。
- 未知或 API-compatible Provider，如果模型名唯一匹配一条官方规则，或在 token 边界上以最长已知
  全称唯一匹配一条官方规则（例如区域/部署后缀），会保留原始 Provider 并标记为 `estimated`。
- 回退匹配只用于没有自己规则的模型：多出来的后缀如果命中价格敏感词，不会借用更短的已知模型价；
  有独立规则的模型走正常匹配，不受这条限制。
- 这是按公开价推算，不代表中转服务的实际账单。

具体费率请以插件内「计价设置 → 模型价格」显示的目录为准，不在文档里复制价格表。
目录的采集、签名与维护流程见 [动态价格设计](pricing-updates.md)。

### 3.6 计价设置抽屉

头部的齿轮图标从右侧打开「计价设置」抽屉：桌面宽 560px，窄屏使用面板全宽。
抽屉固定三个分区。

**模型价格**

- 默认优先展示已用模型，可切换到全部模型、搜索，或按模型组分页（每页 25 个模型组）。
- 点开模型可查看完整 Provider/模型、当前规则、来源（官网定价）和折叠的「其他时期价格」。
- 简单价显示输入/输出摘要；复杂价显示「分档价格 · N 条当前规则」。
- 待计价模型可以直接「设置价格」，会带上已填好的供应商和模型。

**自定义规则**

- 规则列表与添加/编辑页分开，底栏统一提供「预览影响 / 保存 / 取消修改」。
- 填写供应商 ID、模型 ID 和每百万 token 单价（非缓存输入、缓存读取、缓存写入、输出）。
  留空表示未知，填 `0` 才表示免费。
- 「更多条件」支持生效时间、结束时间、账户类型、长上下文阈值和服务档倍率。
  未指定生效时间时，历史用量按该费率估算；指定后规则只在对应时间范围内生效。
- 生效和失效时间与面板其余部分一样按北京时间（UTC+8）填写和显示。
- 加入草稿、待移除与撤销移除都在本地规则集合中完成；表单还有未加入的修改时不能预览或保存。
- 关闭抽屉会放弃未保存的修改。

**更新与版本**

- 展示当前目录的完整版本号、真实发布时间、上次检查、上次成功同步、自动更新开关和历史目录快照。
- 自动更新开关修改后需要预览并保存才生效。
- 历史目录快照初始显示最近 5 个，每次「查看更多」追加 5 个；恢复会替换整个目录并暂停自动更新，
  已保存的自定义规则保留。
- 固定版本时两个「检查更新」入口都禁用；重新开启自动更新并保存只解除固定，不会自动下载，
  之后可以手动检查。
- 未固定且自动更新关闭时仍允许手动检查。
- 更新失败继续使用上次有效版本。

模型详情里的「其他时期价格」只是该模型的历史规则；「更新与版本」里的「历史目录快照」是整个
签名目录的版本，两者不是同一层数据。供应商自定义价格优先于公共目录。

### 3.7 自动更新

- 宿主启动时及之后每小时检查经过签名的价格目录。
- 遇到缺价模型会触发一次有冷却时间的检查。
- 自动更新只下载公共目录，不上传会话或凭证。
- 本地目录位于 `$DSH_HOME/plugins/dsh-stats/pricing/`（默认 `~/.dsh/plugins/dsh-stats/pricing/`），
  包含有效价格、历史目录与自定义设置修订。原始 token 日志不会被改写。
- 浏览器离线降级时，面板会标明「本地摘要 · 内置价格」。

## 4. 账户与凭证

账户查询只在宿主侧执行。下表中的凭证引用是变量名，不是需要粘贴到 README 或聊天窗口的密钥值。

| 账户 | 官方接口 | 默认凭证引用 |
| --- | --- | --- |
| DeepSeek 余额 | `/user/balance` | `DEEPSEEK_API_KEY` |
| OpenRouter Credits | `/api/v1/credits` | `OPENROUTER_MANAGEMENT_KEY`（必须是 Management Key） |
| Moonshot 余额 | `/v1/users/me/balance` | `MOONSHOT_API_KEY` |
| Z.ai 余额 | `/api/paas/v4/balance` | `ZAI_API_KEY` |
| Kimi For Coding | `/coding/v1/usages` | `KIMI_API_KEY` |
| Z.ai Coding Plan | `/api/monitor/usage/quota/limit` | `ZAI_API_KEY` |
| MiniMax Coding Plan | [`/v1/token_plan/remains`](https://platform.minimaxi.com/subscribe/token-plan?tab=api-enterprise)（含官方兼容路径） | `MINIMAX_API_KEY` |

- Provider 配置中的 `accountApiKeyEnv`（也接受 `accountApiKeyRef` 等写法）可以覆盖默认引用。
- 查询结果缓存 5 分钟并合并并发请求；点刷新会明确绕过这层缓存。
- 单个账户遇到网络错误、限流或异常响应时，会保留该账户上一次成功快照并标为「已过期」。
- 整次查询失败时：已有上次成功结果则标题变「快照已过期」，上方出现可重试的横幅，账户行保持可见；
  首次失败则标题显示「读取失败」，重试在账户区里。
- Harness 0.1.7 新增的 DeepSeek 账户登录方式（`deepseek-account`）不使用 API Key，
  官方余额接口无法查询，账户页不会列出它；API Key 方式照常查询。
- 未声明账户类型的 MiniMax 旧配置继续默认使用 Coding Plan；显式配置 `accountType: api`
  时不会当作订阅额度查询。
- 没有公开余额接口的 Provider 仍会统计 Token，账户页把它们列在「未接入」组并说明原因；
  已配置接口但缺少凭证的账户会单独列出缺少的变量名。

## 5. 数据来源、导出与操作

### 5.1 数据来源与状态

面板里有三处相关提示，触发条件不同。

**标题状态点**跟着当前标签页：

| 标签页 | 界面文案 | 什么时候出现 |
| --- | --- | --- |
| 统计页 | 已同步 | 宿主 RPC 返回统计数据且没有降级；时间线按事件时间戳切成 30 分钟槽。 |
| 统计页 | 数据不完整 | 宿主标记了降级（日志缺失、正在写入或校验未通过），已知值仍然显示。 |
| 统计页 | 快照已过期 | 这次读取失败，但已经有过一次成功结果。 |
| 统计页 | 本地摘要 · 内置价格 | 浏览器没有拿到统计 RPC（旧宿主，或插件没加载成功），或者第一次读取就失败；改用可见的投影值估算，并使用内置价格。 |
| 账户页 | 已同步 | 这次账户查询成功。 |
| 账户页 | 快照已过期 | 有上次成功结果，但这次查询失败。 |
| 账户页 | 读取失败 | 第一次查询就失败，还没有可用结果。 |
| 账户页 | 账户服务不可用 | 宿主没有提供账户 RPC。 |

**失败横幅**出现在内容上方，用另一套文案，并按条件附带「数据诊断」和重试：

| 标题状态 | 横幅文案 | 数据诊断 | 重试按钮 |
| --- | --- | --- | --- |
| 快照已过期 | 刷新失败，显示上次快照 | 有错误信息时显示 | 有对应的统计或账户 RPC 时显示 |
| 本地摘要 · 内置价格 | 回退数据，可能不完整 | 有错误信息时显示 | 仅当宿主仍提供统计 RPC 时显示 |
| 数据不完整 | 数据不完整 | 有告警或错误信息时显示 | 不显示 |
| 已同步（带告警） | 已同步（信息样式） | 显示 | 不显示 |

账户页只有「快照已过期」出横幅；第一次查询失败（标题「读取失败」）和「账户服务不可用」都不出
横幅，前者在账户区里提供重试。统计页完全拿不到统计 RPC 时，横幅是信息样式，也没有重试。

**本地摘要 · 内置价格**只属于统计页，表示浏览器侧在估算；账户查询失败不会触发它。

「已同步」描述的是**数据来源**，不是单价确定性：数据同步成功时，金额仍可能是 `estimated`
或 `partial`。反过来，计价为 `exact` 也不代表这份日志一定完整。

### 5.2 时区

时间线、峰谷时段、日期范围和计价规则的生效时间都使用显式北京时间（UTC+8），不受宿主机系统
时区影响。

### 5.3 导出

- 项目总览、开发时间线、用量趋势支持 CSV 和 JSON。
- 导出的是**当前范围选中的项目**：总览和时间线取当前日期（选「全部」时是全部项目），趋势取当前
  区间；隐藏的项目也会包含在内。
- JSON 是这些项目的数组，不是完整的 RPC 响应，`meta` 和 `meta.warnings` 不在其中。每个项目的
  会话用量保留宿主返回的 `cost` 对象。
- 界面和汇总只用人民币。USD 原价按固定汇率换算，换算后的金额进入 `estimated`，不会被描述成
  确定的 Provider 账单。
- JSON 的每条用量有 `cost.status`、`cost.ruleId`、`cost.sourceUrl`；USD 计价的用量另有
  `cost.pricing.nativeAmount`、`nativeCurrency`、`fxRate`、`fxDate`、`fxSource`，可以核对原币
  金额和当时用的汇率。
- CSV 是扁平的项目表格，每条用量一行；`costStatus` 是该行的 `cost.status`，`pricingSource`
  是该规则来源的 URL（对应 JSON 里的 `cost.sourceUrl`）。CSV 有 `currency`、`costAmount`、
  `exactAmount`、`estimatedAmount` 等列，没有原币金额列。
- 两种导出都没有排除原因的文本；原因在面板的会话详情里。
- 账户余额页不提供导出：余额属于实时快照，不属于历史统计。
- 凭证不会进入 CSV/JSON 导出。

### 5.4 键盘操作

- `Tab` 在面板内循环。
- `Esc` 依次关闭筛选、菜单和价格抽屉，最后关闭面板。
- 表头按钮按 `Enter` 排序，展开按钮按 `Enter` 展开/收起。

## 6. 已知限制

- 当前会话的 projection cache 可能滞后几秒，面板每 60 秒自动刷新。
- 普通归档会话会标注「已归档」；归档、无日志且只有继承 cache 的 fork 会从统计中排除，
  并在告警中说明原因。
- OpenRouter 使用带日期的模型目录快照，这类金额会标记为 `estimated`。
- 未知 API Provider 只在模型唯一匹配、或按最长已知全称前缀唯一匹配官方规则时给出 `estimated`；
  回退匹配时多出来的后缀命中价格敏感词就不再借用更短的模型价。
- 同一项目的并发会话在时间线中合并为墙钟区间，项目 LLM/工具时长仍是累计工作量指标。
- 界面目前提供中文和英文。
