账户余额改版

余额页从“下拉框选一个、看一个”改成一屏列出全部账户，按紧急程度排序；多账户时顶部用一条摘要回答“还剩多少、哪个最紧”。面板里的账户和金额都是虚构示例。可以直接操作：切换示例、主题和宽度；点余额行右侧的铃铛设置“余额低于多少时提醒”；悬停或聚焦重置时间看北京时间；展开底部的“未接入”。刷新按钮会模拟一次刷新；“刷新失败”示例点刷新或“重试”后恢复正常，“首次加载”停在骨架状态方便查看。

现在的问题

  1. a一次只能看一个账户。配了多个 Provider 时，要逐个切下拉框才知道哪个快用完了。
  2. b下拉框标签会重名。标签优先显示 providerFamily，moonshotai 和 kimi-coding 都显示成 “moonshot”。
  3. c状态只看第一个账户。页面状态和警告取 accounts[0] 和 warnings[0]，和当前选中的账户可能对不上；警告是宿主的英文原文。
  4. d两种卡片外观。DeepSeek 有专属渐变卡（12 个专用 token），其他 Provider 是普通卡片，切换账户时视觉重量跟着变。
  5. e空间利用差。1440px 下一张卡只占面板约 1/3 的高度；充值、赠送两个框各占半宽，里面只有一个数字。
  6. f订阅信息主次颠倒。套餐名出现三次，用的是全页最大字号；额度数字反而是小字。
  7. g额度条读反了。条画的是已用，旁边写“68% 剩余”；额度低时不变色，重置时间只有绝对时刻。
  8. h和另外三页不一致。标题重复 tab 名，头部没有状态点，加载时只有一行文字。

改动要点（对应面板里的编号）

  1. 1头部状态点：和其他页一样显示“已同步 · HH:MM”“正在刷新…”“快照已过期”，去掉正文里的“更新时间”和每张卡的“上次成功”。
  2. 2摘要条：可用余额（按币种分别合计，不换算）、最紧的额度、需要关注的账户数。只有一个账户时不显示。
  3. 3全部账户一屏列出，按紧急程度排序：需要处理 → 需要关注 → 正常。下拉框删除。
  4. 4统一的账户行：状态点、名称，副行是类型和套餐或路由 id，同一 family 的账户不会重名。不再有 DeepSeek 专属渐变。
  5. 5余额与额度同一列：金额右侧是构成（充值 · 赠送、已用 / 总额）。额度条表示剩余，低于 20% 变琥珀色，低于 5% 变红；重置时间写成“2 天后重置”，悬停显示北京时间。
  6. 6异常才有标签：额度紧张、额度已用完、余额偏低、余额已用完、凭证无效、已过期等，原因写在金额下方，文案本地化，不再透传宿主英文。正常的账户只有绿色状态点，没有标签。
  7. 7余额提醒：每个余额账户右侧有一个铃铛，点开填“低于多少时提醒”。设了的账户在金额旁显示“提醒线 ¥20.00”，铃铛变蓝；余额低于提醒线时显示琥珀色“余额偏低”，排到前面，并计入“需要关注”。默认不设，余额为 0 时始终显示红色“余额已用完”。
  8. 8未接入的账户折叠成最后一行，展开后列出缺少的凭证键名或“不支持”。
  9. 9页面横幅只在整个查询失败时出现：写明显示的是几点的快照，诊断信息可展开，有“重试”。单个账户失败只在它自己的行里显示。
  10. 10首次加载用骨架行：账户名来自宿主已有的 stats/providers，数值是占位。

数据从哪来（不改宿主接口）

  • ·账户列表沿用 stats/account 的 accounts[]，字段不变；紧急程度、标签、排序、汇总都在客户端纯函数里算（计划放在新的 client-balance-model.cjs）。
  • ·余额按币种分别合计，不做汇率换算；非人民币金额显示为 $15.50，不再是 15.50 USD。
  • ·余额页只用账户接口的数据，不读会话统计；“近 7 天消耗 · 可用天数”已确定不做。
  • ·余额提醒存在新的本地偏好 dsh-stats.balanceAlerts，形如 { "deepseek-official": { "amount": 20, "currency": "CNY" } }，和 dsh-stats.hidden 一样用 usePref 读写。只和同币种的余额比较；账户币种变了，提醒自动失效，不做换算。不经过宿主，也不改 RPC。
  • ·首次加载的骨架行来自 stats/providers（客户端已注册，目前没有调用）；旧宿主没有这个方法时显示 3 行空骨架。
