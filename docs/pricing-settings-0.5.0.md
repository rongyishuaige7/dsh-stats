## 1. 现状与问题

以下问题已对照基线源码核实。

| 现状 | 影响 | 代码证据 |
| --- | --- | --- |
| 同一长页依次放自动更新、同步、待计价、完整自定义表单、价格目录、目录历史快照 | 日常查价与低频维护互相挤占空间，版本入口藏在目录底部 | `src/pricing-panel.cjs` 的 `PricingPanel` |
| 抽屉宽 460px，目录又有 `max-height:420px; overflow-y:auto` | 宽屏仍拥挤，滚轮在两层正文间切换 | `src/client-styles.cjs` 的 `.dss-drawer`、`.dss-price-catalog-list` |

## 2. 目标与非目标

### 2.1 目标

- 打开齿轮先看到模型价格，快速搜索自己使用过的模型。
- 一个 Provider＋模型一行，当前价、分档价、历史价层次清楚；不丢价格条件和来源信息。
- 自定义规则默认是列表，主动添加或编辑时才显示表单；分区切换保留本次草稿。
- 自动更新和整个目录的历史快照集中到“更新与版本”；固定旧版本时明确说明实际生效状态。
- 与其余四页使用同一套主题、字号、细线、控件与键盘行为。

### 2.2 非目标

- 不扩展计价引擎、账户类型、费率模式、汇率或数据来源；不调整费用数值和规则优先级。
- 不把抽屉扩展为通用设置中心，不增加外观、账户、备份、导入导出或云同步设置。
- 不增加版本差异、历史版本发布时间、更新说明、快照删除或清理功能；当前 RPC 没有这些数据。
- 不改变“预览后保存”、修订号冲突保护、签名校验、版本恢复和自动更新的宿主语义。
- 不把草稿写进 localStorage，不跨关闭、面板重开或应用重启保留未保存内容。

## 3. 数据与协议约束

### 3.1 已有数据

| 数据 | 来源与含义 | 实施限制 |
| --- | --- | --- |
| 计价状态 | `status` 返回 `version/publishedAt/fingerprint/revision/autoUpdate/pinnedVersion`，以及检查、同步时间和错误 | 当前生效版本以返回值为准，不能取历史列表最大值代替 |
| 价格目录 | `status.catalogJson`，通过 `pricing.validateCatalog` | 目录和自定义规则分别展示，不合成为一份伪官方目录 |
| 已保存自定义规则 | `status.overridesJson`，通过 `pricing.validateOverrides` | 与正在编辑的表单、已加入本次草稿的规则集合分开 |
| 全量使用记录 | `StatsPanel` 传入 `data.projects` | “已用”和抽屉待计价列表都看全部已加载项目历史，包含被筛选隐藏的项目；不跟随总览日期或趋势范围 |
| 已用模型身份 | `usedModelKeys(projects, catalog)` | 保留现有 `ruleId`、引擎匹配与身份归一化路径，不用模型名包含关系猜 Provider |
| 待计价模型 | `missingModels(projects)` | 沿用现有按未计价 Token 降序的结果，不扩大订阅与未知身份的识别语义 |
| 外部定位 | `focusModel={provider,model,nonce}` | Provider 和模型分别传递，同名不同 Provider 不能串；同一个模型再次点击也能触发 |
| 历史目录快照 | `status.history`，只有数字版本号数组 | 没有旧快照的发布时间、规则数和差异；禁止解析版本号伪造这些信息，也不增加 RPC |

基线签名目录版本为 `2026101816`，有 873 条规则、384 个 Provider＋模型组。这是交接时的快照，测试和页面都必须从实际目录动态计算，不能硬编码这些数字。价格机器人可能在实施期间更新目录。

### 3.2 请求协议

| 动作 | 请求 | 成功后的处理 |
| --- | --- | --- |
| 初次打开 | `{action:'status'}` | 校验并装载已保存状态；等待中的 `focusModel` 随后定位 |
| 检查更新 | `{action:'refresh'}` | 按返回状态更新；若 `result.error` 非空，显示同步失败，继续使用返回的有效目录 |
| 预览影响 | `{action:'preview', overridesJson}` | 只更新预览，不用它重置本地表单、规则草稿或自动更新草稿 |
| 保存 | `{action:'save', overridesJson, autoUpdate, fingerprint, revision}` | 使用有效预览的 fingerprint 与本次编辑基线 revision，成功后装载返回状态并清草稿 |
| 恢复快照 | `{action:'rollback', version, revision}` | 使用已保存状态的 revision；成功后自动更新为 false，当前版本被固定，自定义规则保留 |

- 同一抽屉实例初次装载请求一次 `status`。切分区、搜索、翻页、进入详情、返回都不发 RPC。
- 预览读取 `previewJson` 的 `before/after/changed`；不能只在本地重新计算后当作宿主预览。
- 请求期间禁止新的变更请求，锁住输入和会改变草稿的控件。分区浏览、返回和关闭仍可用。
- 仅成功返回的 `refresh/save/rollback` 沿用现有 `onChanged()` 接线，触发统计重新聚合；`status/preview` 和纯浏览不触发。
- 宿主会在下载失败时返回带 `error` 的状态，而不一定 reject。不能只靠 Promise 是否 resolve 显示“同步成功”。

### 3.3 保持原有计价语义

- 单价单位仍为每百万 Token；`null`/空输入表示未知，`0` 表示免费，不能互换。
- 模型价格展示保留 CNY/USD 原币种；本轮不把价格目录统一换算成人民币。
- `effectiveFrom` 含起点，`effectiveTo` 不含终点；`observedFrom` 不是“未来生效”。展示与 `datetime-local` 输入按北京时间 UTC+8 处理。
- 未填生效时间时，已有历史用量按该自定义价格估算；已有 `draftRule()`、`ruleDraft()` 的字段转换语义保持。
- 上下文阈值、长上下文单价、priority/batch/flex 倍率、api/relay/local 账户类型与同身份时间重叠校验保留。
- 自定义规则优先级、订阅不按 API 单价计费、思考 Token 计入输出等语义保持，不由 UI 重新解释。

## 4. 已锁定的设计决策

### P1 抽屉骨架

- 保留 `aside.dss-drawer[role=dialog][aria-modal=true]`，覆盖现有面板右侧。
- 标题改为“计价设置 / Pricing settings”；齿轮的 aria-label、title 使用同一文案。
- 桌面 `width:min(560px,100%)`，视口不超过 640px 时全宽，受现有面板边界限制。不得根据屏幕宽度硬写抽屉位置。
- 固定头部、固定分区导航、中部一层正文滚动、条件出现的底部草稿操作区。正文唯一滚动容器仍叫 `.dss-drawer-body`。
- 删除价格列表、规则详情和版本列表内部的限高滚动。外层 `.dss-body` 沿用原有面板滚动策略，抽屉内不再增加第二个正文滚动层。

### P2 三个分区与内部页面

顶层顺序固定为“模型价格 / 自定义规则 / 更新与版本”，默认模型价格。使用按钮分段控件，`role=group`、完整 aria-label、各按钮 `aria-pressed`，沿用现有分段按钮的键盘约定。

- 模型详情属于“模型价格”，带“返回模型列表”；编辑表单属于“自定义规则”，带“返回规则列表”。都替换抽屉正文，不打开第二个弹窗或抽屉。
- 顶层分区切换保留搜索、筛选、页码、当前详情、表单、规则草稿与预览；不因子组件卸载重建状态。
- 切到某分区时恢复它的内部页面；通过“添加规则”“设置价格”等明确入口才改变内部页面。
- 搜索或筛选改变时页码回 1；返回列表恢复原搜索和页码，并将该行滚动到可见、焦点还给该行按钮。不要求精确恢复像素滚动位置。
- 新实例由齿轮进入时恢复默认模型列表；不持久化上次分区。

### P3 模型价格首页

从上到下：紧凑同步摘要 → 待计价提示（有则显示）→ 搜索 → 已用/全部切换与数量 → 模型列表 → 分页。

- 同步摘要只占一至两行，展示当前目录版本、上次成功同步时间和“检查更新”。详细更新设置放第三分区。
- 待计价提示显示模型数与可操作条目；超过 3 个时先展示前 3 个，加“展开其余 N 个”，展开后仍由抽屉正文滚动。每条显示 Provider、模型和“设置价格”。
- 已用筛选至少匹配到一个目录模型时，初始选“已用模型”；否则选“全部模型”，显示“暂无已用模型记录，可浏览全部价格”。刷新后不强制改用户已选筛选。
- 筛选范围只作用于价格目录；搜索时仍受已用/全部约束。无结果时给清空搜索或切到全部的明确入口，不静默扩大搜索范围。
- 数量明确写“X 个模型 · Y 条价格规则”：X 是匹配模型组数，Y 是这些组中所有时期规则总数。分页基于模型组，每页 25 个；同一个模型的规则不跨页拆散。
- 目录中只有历史或未来规则的模型仍可被找到，摘要显示“暂无当前价格”，历史与未来规则在详情中查看。

### P4 模型分组、排序与摘要

- 复用 `groupKey`：`[providerId || 'family:'+family, canonical]`。不同 Provider、canonical 和真实 thinking 变体不能因名称相近合并。
- 保留 `catalogGroups()` 现有“已用优先 → DeepSeek 优先 → Provider → canonical”顺序，搜索覆盖模型 canonical、Provider 与 aliases。
- 每行是可聚焦的详情入口，展示模型名、Provider、已用标记、价格摘要；provisional 继续显示“自动接入，待复核”。不再一段价格规则占一行。
- **简单价**：只有一条当前规则，费率模式为 `rates`，且没有非 1 的服务档倍率时，显示“输入 ¥X / 输出 ¥Y”，同时显示币种与适用账户类型；规则未限定账户类型时不能擅自标为 api。完整四项价格在详情。
- **复杂价**：多条当前规则、上下文分档、服务档、时段、legacy 模式或非 1 倍率，一律显示“分档价格 · N 条当前规则”，不调用 `primaryRates()` 把其中一档当通用价。
- **没有当前规则**：显示“暂无当前价格”，附历史/尚未生效数量。
- 简单价中的未知值显示“未知”，免费显示 `¥0/$0`。保留 `fmtRateValue()` 的 8 位有效数字与极小价格行为，不能统一 `toFixed(2)`。
- 模型名在宽处可省略；详情必须完整可复制，窄屏与长 Provider 可自然换行，不能依赖横向滚动或 title 才读得到身份。

### P5 模型详情不丢信息

顶部为返回、完整 Provider/模型与单位。当前规则全部展示；历史与未来规则放该模型下的“其他时期价格”折叠区，默认折叠。

| 内容 | 详情要求 |
| --- | --- |
| 规则身份 | 账户类型、币种、当前/历史/尚未生效、待复核状态；必要时展示规则 ID 为次级文字 |
| 基础费率 | 非缓存输入、缓存读取、缓存写入、输出四项，未知与 0 区分 |
| 上下文与服务档 | 标准/长上下文、阈值、standard/priority/batch/flex 分档及倍率；不能丢长上下文数据 |
| 时段与旧费率 | legacy、peak/offPeak、`timeOfUse` 两段费率、北京时间日历范围和日历来源；保持 `ruleDetails()` 原有信息能力 |
| 时间 | 生效起止、核验时间、价格采集日期，明确北京时间和终点排他 |
| 来源 | 备注、官网链接与原币种单位；链接保留 `target=_blank`、`rel=noreferrer` |

- 当前规则在前；其他时期规则按现有生效/核验时间倒序，并以规则 ID 打破相同时间的排序平局。
- 明示“目录价格”，自定义规则不改写其摘要。提供“为此模型添加自定义规则”，只预填 Provider 和模型，不复制不确定的首档价格。
- 若有 Provider＋canonical 精确匹配的已保存自定义规则，列出独立的“已保存自定义规则”入口，跳到相应编辑；不把本次未保存规则宣称为已生效。跨别名的实际匹配仍由引擎负责，不在 UI 猜测。
- 没有目录记录的待计价模型仍可直接新建自定义规则；不为它伪造官方模型行。
- 模型的历史价格是只读详情。恢复整个目录只在“更新与版本”，不得在每条模型历史价旁放“恢复”。

### P6 自定义规则列表与编辑

- 默认显示规则列表和“添加规则”，不把所有输入框常驻首页。无规则时用一段简短说明和添加按钮。
- 列表每行显示 Provider、模型、币种/价格类型、生效条件摘要、编辑、移除；复杂条件在行内可展开只读查看。
- 新增、编辑打开同一编辑页；顶部返回规则列表不会撤销表单。编辑页恢复时保留原字段与展开状态。
- 基础字段直接显示：Provider ID、模型 ID、币种、四项单价；条件区默认折叠，包含北京时间起止、阈值、长上下文四项费率、三种服务档倍率与账户类型。
- 编辑已有非默认条件的规则时，条件区自动展开，并显示“已设置条件”，避免隐藏实际适用条件。
- 单位提示紧邻费率：“每百万 Token；留空表示未知，0 表示免费”。生效时间提示明确未填时的历史估算语义。
- 表单按钮继续叫“加入草稿 / 更新草稿”，只校验并更新本地规则集合；不得直接发 `save`。成功后回列表，条目标注“未保存”。
- “取消编辑”只撤销当前表单并返回列表，不撤销已加入的其他规则草稿。底部“取消修改”撤销整个抽屉本次尚未保存的表单、规则和自动更新改动。
- 移除只更新本地规则草稿；对已保存规则显示“待移除”及撤销入口，保存成功才从生效列表消失。不增加宿主删除接口。已保存规则编辑后生成的新 ID 继续沿用现有转换逻辑，不能仅凭旧 ID 消失就把它重复显示为待移除；待移除标记只来自明确的移除操作。

### P7 两层草稿与底部操作区

必须区分以下状态，不能只沿用原来一个 `dirty`：

1. **表单编辑**：`draft/editingId/editorBaseline/editorDirty`，还没有加入本次规则集合。
2. **待提交设置**：`workingOverrides/autoUpdateDraft` 对比已保存 `status.overridesJson/status.autoUpdate`，派生 `settingsDirty`。新增、修改、删除规则和切换自动更新都属于这里。

- 预填一个新模型或打开已保存规则，建立表单基线，本身不算修改；之后任一字段改变即按基线比较 `editorDirty`。
- 只要 `editorDirty || settingsDirty`，固定底部操作区出现，三个按钮为“预览影响 / 保存 / 取消修改”，附“未保存；关闭计价设置将放弃修改”。
- `editorDirty` 时，预览和保存不可用，显示“请先加入草稿或取消编辑”；提供“继续编辑”入口。不能保存时静默漏掉当前输入，也不能悄悄代替用户把表单加入草稿。
- 表单已加入规则集合、只改自动更新、移除规则这三种情况，都走同一个预览后保存流程。没有任何修改时不显示空操作区。
- 预览显示影响会话数与前后费用；按返回值的币种分别展示，不把 USD/CNY 直接相加为一个数字。影响范围是宿主聚合数据，不写成当前总览日期。
- 修改任一表单字段、规则集合或自动更新开关时，已有预览立即失效；切分区、搜索、分页、返回不使预览失效。
- 保存按钮只有在设置确有修改、表单没有未加入的修改、当前预览有效且非 busy 时可用。必须发送当前规则集合、当前自动更新草稿、有效预览 fingerprint 和编辑基线 revision。
- 成功保存后清空表单、移除待删除标记、清预览与 dirty，保留所在顶层分区；自定义编辑回列表。不能自动关闭抽屉。

### P8 草稿生命周期、关闭与错误

| 操作 | 草稿与预览 | 焦点或反馈 |
| --- | --- | --- |
| 切分区、查看模型、返回列表、搜索、翻页 | 全部保留；预览仍有效 | 按 P2/P14 |
| 另一个模型的添加/编辑/设置入口 | 若当前表单有未加入修改，不替换字段；若无则可进入新表单 | 有修改时显示行内说明与“继续编辑”；先加入草稿或取消编辑，再操作另一模型 |
| 明确取消编辑 | 只撤销当前表单，清其编辑标识；已提交到本地集合的规则不动 | 返回规则列表 |
| 底部取消修改 | 回到最近一次成功装载的已保存状态；清表单、规则草稿、开关草稿和预览 | 保留顶层分区，焦点到其标题或添加入口 |
| Esc、关闭按钮、抽屉遮罩关闭 | 沿用当前卸载即放弃未保存内容，不另加确认弹窗 | 关闭前已有底部说明；关闭后恢复 opener，来源消失回齿轮 |
| 外层面板遮罩关闭，随后重新打开 | 抽屉关闭，本次未保存状态全部清除 | 保留原面板重开焦点规则 |
| 预览或保存失败 | 保留表单、规则与开关草稿；清失败/过期预览 | 本地化错误可见，用户可取消修改或重新操作 |
| `pricing-settings-conflict` | 不用新 status 静默覆盖本地输入，不自动重试保存；禁用旧预览保存 | 告知其他页面已更新，请复制所需输入后关闭并重开；新实例重新取状态 |

待提交改动存在时，检查更新和恢复版本都禁用并说明“请先保存或取消修改”，避免 `accept()` 覆盖草稿。表单未修改的预填不算待提交改动。

关闭不会撤销已发出的 `save/rollback/refresh`。异步回调要有实例生命周期保护：不向已卸载页面写状态、不自动重开；已经成功完成的变更仍按原有回调刷新父级数据。不要承诺前端关闭能取消宿主操作。

### P9 待计价定位与重复入口

- 外部待计价 chip 直接进入“自定义规则 → 新建规则”，保留目前“设置价格”直达能力，不先要求用户搜索目录。
- `status` 未返回时缓存最新定位，返回后再预填；不能因装载 `accept()` 把定位清空。
- 预填后滚动表单到可见，焦点落第一个 Provider 输入；仅此明确定位入口覆盖常规开抽屉时关闭按钮的初始焦点。
- 同 Provider＋模型再次定位时：有该模型未完成表单则恢复它，不覆盖输入；无编辑则可新建。不同模型且有表单修改时遵循 P8，保存待定位目标供用户处理完表单后再次选择，不自动替换。
- nonce 保留，不能用字符串相等去吞掉用户的再次定位动作；内部定位不能反复请求 `status`。
- 总览、项目行、趋势页既有 chip 接线与 `stopPropagation()` 保留。关闭恢复到各自来源；来源因保存或刷新消失时回齿轮。

### P10 更新与同步状态

“更新与版本”按顺序显示：当前生效目录摘要 → 同步与自动更新 → 历史目录快照。

- 当前摘要展示完整版本号、真实 `publishedAt`、是否手动固定；不能把数字版本号格式化成假日期。
- 上次检查用 `lastCheckAt`，上次成功同步用 `lastSuccessAt`；无值显示“尚未检查 / 内置目录，尚未成功同步”。当前目录的发布时间不冒充上次同步时间。
- 自动更新是草稿开关，旁边说明“修改后预览并保存才会生效”，未保存时标注“待保存”。切换开关只更新草稿，不直接发保存请求。
- 未固定且自动更新已关闭时，仍允许“检查更新”：现有强制刷新可以激活新目录。页面说明自动更新只控制后台更新。
- **已保存 `pinnedVersion !== null` 时，两个分区的“检查更新”都禁用**，说明“当前已固定版本；开启自动更新并保存后可检查更新”。即使草稿开关已经勾上，保存成功前仍禁用。
- 重新开启自动更新并保存，只解除固定，不代表已经下载或切到最新版；返回当前版本后，用户可另点检查更新。不能链式偷偷调用 refresh。
- 检查更新期间显示正在检查、禁止重复；失败保留有效价格并展示本地化说明；不显示宿主原始异常文本为主文案。

### P11 历史目录快照

- 标题完整写“历史目录快照 / Catalog snapshots”，附“恢复会替换整个目录并暂停自动更新；已保存的自定义规则保留”。
- 当前生效版本始终在顶部摘要可见，不依赖它是否在 `history` 数组中。
- 历史列表对 `history` 做正安全整数过滤、去重、数值倒序，排除当前版本。初始展示最近 5 个可恢复快照，每次“查看更多”追加 5 个；没有更多时隐藏按钮。
- 每行显示原始版本号与“恢复此版本”。不补写发布时间、变更条数或版本说明。历史为空时显示“暂无可恢复的目录快照”。
- 恢复只发送选中版本和当前 revision，不能先清自定义规则。存在未保存修改或请求进行中时禁用。
- 成功后保留“更新与版本”分区，刷新当前版本、自动更新 false 和固定标记；恢复后的版本从可恢复列表移除，重置为最近 5 个。
- 恢复失败保留当前已保存状态和列表、显示错误；不要在 RPC 返回前先改当前版本或开关。
- “查看更多”只是前端显示，不下载历史文件、不删除磁盘快照、不读取额外 payload。

### P13 加载、空态与失败

- 首次 `status` 加载时保留标题、导航和正文加载提示，变更按钮禁用；不要先闪现空版本列表或 0 元。
- remote 缺失时显示本地化“计价设置暂不可用，请确认插件版本”，保留关闭和键盘行为。
- status 请求失败时显示重试。重试属于装载状态的显式请求，不把分区切换变成隐式重试。
- 目录为空、搜索无结果、没有已用模型、没有自定义规则、没有历史快照，分别给具体空态；都不能阻断其他分区。
- 保留 `PricingErrorBoundary`，渲染失败能重试，不把错误边界提示隐藏在重复标题规则里。

### P14 键盘、焦点与滚动

- 沿用 `LayerContext/useLayer`、输入法组字 Esc 保护、`trapTab` 和原焦点恢复，不额外注册 window/document 的 Esc 监听。
- 普通齿轮打开时聚焦关闭按钮；Tab/Shift+Tab 在抽屉全部可见控件中循环。
- 分区按钮按自然 Tab 顺序，Enter/Space 切换；切换后焦点留按钮。内部进入详情/编辑时将焦点放到可聚焦标题或首输入，返回恢复原入口。
- **Esc 始终关闭整个抽屉**，不是在详情和列表间返回；返回必须有明确按钮。下一次 Esc 才关闭主面板，输入法取消候选词不关任何层。
- 分页或版本“查看更多”引发按钮卸载/禁用时，焦点移到列表标题或首个新条目；不能落到 body。保存成功后若原焦点按钮消失，回到当前分区标题或添加入口。
- 请求错误用 `role=alert`，预览、保存成功和待计价数量变化用合适的 `role=status`；不要把整张长列表包成 live region。
- 320px 的长详情和表单只能 `.dss-drawer-body` 纵向滚动，页面与列表不产生横向滚动。底部操作区的全部按钮在短窗口中仍可达。

### P15 文案与实现边界

- 中英文成对进入 `src/pricing-locale.cjs`，复用现有键；新增键不能只改中文。Provider/模型原始标识与协议枚举可以保留原文。
- 规则 phases 保持 current/historical/upcoming，UI 分别显示当前/历史/尚未生效；“目录快照”不再和模型“历史价格”共用一个模糊标题。
- 新增的列表、详情、编辑可以拆为定价专用组件；不要迁移四页通用框架或抽出新的应用级状态库。
- 浏览器最低版本沿用 Chrome 105+/Safari 16+。不新增依赖、不提高宿主或 React 版本。

### 6.2 纯展示模型建议接口

函数名按以下约定，字段可在不改变契约的前提下局部调整，交付中说明即可。

| 函数 | 输入 → 输出 | 约束 |
| --- | --- | --- |

| `selectModelGroups(groups, {search, scope, page, pageSize})` | 已排序 groups → `{rows, modelCount, ruleCount, page, pageCount}` | scope 为 used/all；按组分页，规则数包含所有时期，页码裁到有效范围；空结果 page=0/pageCount=1 |
| `catalogSnapshotRows(status, limit)` | 状态＋显示上限 → `{versions, total, hasMore}` | 过滤、去重、数值倒序、排除 current，不推测元数据；默认 limit=5 |

`selectModelGroups` 的内部 page 从 0 开始，显示时加 1；默认 search 为空、scope 为 all、page 为 0、pageSize 为 25。生产界面固定传 25，测试可传更小正整数验证分组不跨页；无效 page/pageSize 归一化到默认值，再做页码裁剪。

`catalogGroups/usedModelKeys/rulePhase/fmtRateValue` 保持已有语义。`selectCatalog` 在 6a 保留给旧界面；6b 完成接线且无调用后才可删除或停止导出，并迁移对应旧测试，保留原测试覆盖的身份与时间边界。

纯函数不调用 `Date.now()`、RPC、React 或 localStorage。阶段时间继续在控制器装载有效目录时取样，再显式传给 `catalogGroups`，保证排序与测试稳定。

### 6.3 状态所有权与布局

- `PricingPanel` 在抽屉存活期间只挂载一次。条件渲染的是展示页，不是带请求和草稿的控制器。
- 已保存状态、规则集合、开关、表单、预览、busy/error、待定位目标都在控制器；筛选/分页/当前详情也应高于会被卸载的子页。
- 去掉“任意成功响应都重置一切”的单一路径：明确区分初次装载、预览、保存、刷新、恢复。预览不走装载；有修改时刷新/恢复已禁用。
- 固定导航和底部需要调整 DOM 时，可以让控制器渲染 flex 子布局，再将 `.dss-drawer-body` 放到内部正文。不能在原先已经滚动的 `.dss-drawer-body` 内再包一个滚动正文，也不为放底栏引入 Portal。
- 临时错误不会把分区切回首页；非必要不重置搜索与分页。目录变化后，当前页超界时裁回有效页；详情模型消失则回列表并给简短提示。
