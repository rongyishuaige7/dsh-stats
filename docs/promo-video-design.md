# DSH Usage 宣传视频设计

## 范围

为 DSH Usage 制作一条 30 秒桌面端宣传视频，使用仓库中现有、已脱敏的真实界面截图，输出 1920x1080、24fps 的 H.264 MP4。视频以产品界面为主体，通过连续镜头、扫描、数据流和图表响应展示项目用量、开发时间线、Token 趋势、费用与账户额度。

## 非目标

- 不修改插件功能、界面或现有宣传图。
- 不调用付费图像或视频模型，不生成虚构产品界面。
- 不制作竖屏、配音或多语言版本。
- 不把宣传片实现成重复标题卡、截图轮播或演示文稿式页面切换。

## 动效命题

一条电蓝色数据脉冲从原始会话信号出发，扫描并连接 DSH Usage 的各个真实视图，最终把分散的 Token、时间和费用汇聚成一个清晰的项目判断。

## 动作语法

- 主动作：`flow + scan`，数据脉冲贯穿全片并触发界面状态变化。
- 辅助动作：`camera + merge`，镜头在同一产品空间中移动，最后将视图汇聚。
- 文字只承担品牌、功能短标签和安装命令，不承担完整叙事。
- 至少 80% 的节拍包含扫描、图表增长、路径移动、遮罩切换或空间汇聚等可见状态变化。

## 架构

- `promo-video/source/`：Oil Motion Concept Contract 与 Motion Brief。
- `promo-video/pilot/`：首段 Pilot、首尾帧与审核记录。
- `promo-video/src/`：基于 Canvas 的确定性 1920x1080 合成器和 Chrome CDP 渲染脚本。
- `promo-video/build/`：motion budget、timeline、编码清单和临时帧目录。
- `promo-video/qa/`：关键帧、接触表与解码验证记录。
- `promo-video/final/`：最终 MP4、poster 和运行说明。

浏览器负责按确定时间渲染 Canvas，直接使用 `docs/images/` 下的真实截图。Chrome CDP 逐帧捕获后由本机 ffmpeg 编码；音轨由 ffmpeg 的合成音源生成，不依赖外部素材或服务。

## 风险

- 截图纵横比不同：使用有边界的相机裁切与原生比例缩放，禁止非等比拉伸。
- 中文字体差异：使用 macOS 系统中文字体栈，并在关键帧中检查缺字和溢出。
- 逐帧渲染时间与磁盘占用：Pilot 先以完整分辨率验证渲染链，最终帧目录设为可再生缓存，不纳入 Git。
- 截图式观感：每个节拍必须有主运动对象和状态变化，最终接触表若呈现六张静态幻灯片则返工。
- ffprobe 当前不可用：使用 ffmpeg 解码测试、帧数计算和 macOS 媒体元数据交叉验证。

## 验收标准

- 输出 1920x1080、24fps、约 30 秒、H.264/yuv420p MP4，音轨可解码。
- 全片可由 ffmpeg 从头到尾解码，预期帧数为 720 帧。
- 关键节拍中点的接触表能在不阅读全文的情况下看出总览、时间线、趋势、余额和收束的连续进展。
- 所有截图保持原始比例，无黑边、拉伸、敏感信息或新增虚构数据。
- 文案无溢出，真实界面是每个主要节拍的第一视觉焦点。
- Pilot 在批量渲染前通过首尾帧、短视频、页面证据和人工视觉检查。
- 最终产物、四个事实源、渲染命令和 QA 证据均保存在约定目录。

## 分阶段交付

1. 设计：确认动效命题、节拍图、架构和验收门槛。
2. Pilot：建立事实源、渲染器与首段 4 秒样片，完成硬门检查。
3. 成片：扩展为 30 秒完整时间轴，生成本地音轨并编码最终 MP4。
4. 质检：提取节拍中点、制作接触表、完整解码并核对分辨率、时长和帧数。
