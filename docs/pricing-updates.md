# 动态价格与 Astra 计价

## 已确认范围

补齐 `gpt-6-astra`；价格与插件代码解耦；后台同步经过验证的价格目录；支持供应商自定义费率、预览、历史规则和回滚。主界面统一使用“预估费用”，只显示金额、部分计价的 `*` 或“待计价”。来源、同步状态和规则详情放在价格管理中。

不修改原始会话，不推断供应商实际账单，不按任意相似模型猜价（仅允许最长已知全称、token 边界且唯一匹配的估算回退），不把订阅 token 换算成额外支出。自动更新不上传会话、模型使用记录或凭证。

## 架构与契约

- 纯计价引擎接受不可变目录快照；内置 JSON 提供离线初始版本。宿主统一使用同一快照，浏览器降级计算明确使用内置版本。
- 规则包含供应商、明确模型别名、账户范围、币种、费率、服务档、上下文阈值、有效期、来源、核验时间和修订版本。缺失费率为 null，与免费 0 分开。
- 用户专属规则优先于供应商目录；未知供应商只可使用明确匹配或最长已知全称唯一匹配的原厂参考估算。最长已知全称必须落在 token 边界，`-mini`、`-pro`、`-vision`、`:batch`、`:free` 等价格敏感后缀不猜价；这类回退始终标记 estimated，不能覆盖精确规则。同优先级冲突拒绝。时间区间使用左闭右开。
- 按请求时间计价后汇总；保留目录版本、规则和汇率依据。历史有效期无证据的现价回估必须标记 estimated。
- 官方公开资料：2026-09-17 核验 https://developers.openai.com/api/docs/pricing.md 与 https://developers.openai.com/api/docs/models/gpt-6-astra.md 。Astra Standard 短上下文 input/cache-read/cache-write/output 为 10/1/12.5/50 USD 每百万 token；输入 >272000 时为 20/2/25/75。Batch、Flex 为 0.5 倍，Fast/priority 为 2 倍。yi-api 实际费率未核实。
- 定时采集每 6 小时运行；可信结构化来源通过校验后更新，网页解析生成待审核候选，不自动猜测有效日期或复杂计费条件。
- 官方自动接入：每 30 分钟的签名发布任务解析 OpenAI、Anthropic、Google 官方页面。新模型的无歧义标准价先写入 `[provisional]` 标记的 estimated 规则并自动签名，界面标记“自动接入，待复核”；复核时移除该标记、改为 exact 后再走 `sign_reviewed_catalog`。已有模型调价、退役/受限模型、缺失字段、歧义别名只生成候选，不自动改写。Meta 的 Llama 多为开放权重，价格由托管商决定，不冒充 Meta 官方价；OpenRouter 仅作为第三方参考。目录签名验证、容量和超时限制、版本检查及原子落盘；失败保留上一份有效版本并在设置显示错误。
- 宿主启动后 15–25 秒做首次检查，此后每分钟询问一次：成功后每小时一次，连续失败按 5/15/30 分钟退避，未知模型保留 15 分钟冷却；单次检查对瞬时失败重试（自动 4 次、手动 2 次），签名/版本/容量、408/429 之外的 4xx 等确定性错误不重试。可手动刷新、关闭自动更新、回滚。插件自动更新只下载价格数据，不执行远端代码。
- 自定义规则原子保存，乐观并发检查，保存前预览影响范围；自动更新不覆盖自定义规则。价格变化重算派生费用，不改 token。

## 分阶段交付

1. Astra 与服务档位、简洁费用展示、针对性测试，commit/push。
2. 数据目录、纯引擎快照、历史时间、宿主同步、签名缓存与 RPC，commit/push。
3. 价格管理、覆盖预览、采集工作流、更新说明及浏览器验证，commit/push。
4. 完整测试（含 UTC）、五版本 Harness 契约、浏览器、npm 包检查；发布 minor 版本并升级真实 3080 实例，核对 9.16/9.17。

## 风险与验收

验证 272K 边界、所有服务档、缓存不重复计费、缺失与零费率、跨供应商、有效期交界、目录冲突、断网/损坏/过期/回滚、并发保存、部分计价、CSV 与 UI 一致。旧 RPC 保持兼容；新字段可选，宿主与浏览器版本不一致时明确降级。更新失败不得影响用量采集。生产更新前确认无活跃请求，保留 profile 备份；不修改凭证。

## 维护流程

- `.github/workflows/pricing.yml` 每 6 小时执行，或在 Actions 的 Update prices 手动运行。私钥通过仓库 Secret `PRICING_SIGNING_KEY` 注入，客户端只含固定公钥。
- `node scripts/collect-pricing.mjs` 只生成 `artifacts/pricing/report.json`，不写有效目录。结构化数据范围是 OpenRouter 简单文本模型；官方 OpenAI 网页变化只生成候选，避免漏读上下文、缓存或服务档条件。失败时不会签发任何新目录。
- 复核候选的准确模型 ID、来源、币种、缓存、长上下文、服务档与有效期后，编辑 `data/pricing/catalog.json` 并递增 version。已生效规则保留旧区间，新规则从核验到的时间开始；无历史证据时以 observedFrom 标记早期估算。汇率也是带日期、来源的审核快照，不用实时汇率改写历史结果。
- 在审核分支提交已复核、已递增 version 的目录，再从 Actions 的 Update prices 选择该分支并勾选 `sign_reviewed_catalog`。工作流会在所选分支签名、测试、构建并提交；等 CI 全绿后合并到 main，通过 raw GitHub 分发。未签名的审核分支会被一致性检查拒绝，签名补齐后才能合并。定时采集仍在默认分支执行。候选报告在 Actions artifact，失败会以失败运行呈现。
- `npm run verify:pricing` 校验目录结构、公钥签名及 catalog.json 与签名 payload 的内容一致性；`npm run verify:pricing -- --base-ref HEAD^` 同时校验相对基线的版本。规则、汇率或元数据变化都必须增大 version；版本倒退、同版本改内容、缺失基线历史、错误签名均拒绝。JSON 空白和对象键顺序不影响此项内容比较。
- CI 使用 PR base 或 push before 作为版本基线；采集工作流在写入后与 HEAD 比较；手动签名在写入前与上一份有效签名比较。npm 发布流程与 prepublishOnly 也校验签名和内容，避免打包未签名目录。私钥只用于现有维护工作流，本地验证不需要私钥。
- 机器人提交不会自动触发 push CI，因此价格工作流提交后会显式派发 CI（需要工作流的 `actions: write` 权限），包含浏览器及八版本 Harness 契约；也可在 CI 的 Run workflow 中对审核分支重跑。
- 客户端拒绝错误签名、超限响应、未知 schema、冲突别名、负数费率、未来版本与回退版本。恢复旧版本仅能选择验证过的本地历史快照，后台下载不能覆盖 pin。设置 revision、目录 fingerprint 与跨进程锁防止预览后被其他窗口覆盖；旧设置按修订保留。
- 公钥轮换需要发布插件版本；私钥丢失时先停止签发并安全轮换。日常价格变更不需要 npm 发布。

阶段 3 验证：334 项测试在默认时区及 UTC 通过；Chrome 的 1440/390/320 px 四页签、价格设置预览/保存/编辑、断网保留价格、部分计价点击说明均通过，共 33 张截图，无浏览器错误。公开源 dry-run 成功（247 条结构化候选可更新、32 项待复核），未直接启用网页候选。

阶段 4 发布准备：235 项测试（默认时区/UTC）、五版本契约、完整 Web 的价格 RPC 和浏览器验证通过；目录工作流成功发布 2026091702（286 条规则）。npm 包与 3080 实例交付记录见 [0.4.0 发布说明](release-0.4.0.md)。
