## 2. README 的结构与写法

### 2.1 阅读顺序

中文主入口仍为 `README.md`，英文为 `README.en.md`。`README.zh.md` 继续作为中文跳转页，不维护第三份正文。

1. 项目名、一段用途说明、语言切换、徽章与一张总览图。
2. 安装与升级：桌面端、Web 两个明确入口，说明安装到对应 profile。
3. 四个页面的简短介绍，保留现有有效截图；计价抽屉单独简述。
4. 数据与费用的必要说明：估算、订阅不折算 API 费用、缺价、时区与凭证使用位置。
5. 常见问题：安装后没有入口、费用不完整、账户查不到数据、如何更新；答案简短并链接详细指南。
6. 文档、开发与贡献、MIT 许可。

原有表情标题和颜文字可以保留。主 README 以约 180–230 行为整理参考，不为压行删除必要安装说明，也不通过合并成长行达到目标。

> DSH Usage is a usage dashboard for DeepSeek Harness, available in the desktop app and on the web. Track tokens, development time, and estimated costs by project, and check balances and quotas for configured accounts.

不再在这段前后重复放用途口号、四项加粗卖点和同义副标题。保留品牌 `DSH Usage`、包名 `@rongyi7/dsh-stats`，一句解释两者对应关系即可，不需要讲述命名迁移经过。

### 2.4 安装与发布状态

两个 profile 分别说明，命令以项目已验证的官方 CLI 用法为准，例如：

```bash
# DSH 桌面端
dsh plugin --profile desktop add -w @rongyi7/dsh-stats

# DSH Web
dsh plugin --profile web add -w @rongyi7/dsh-stats
```

- 先确认当前 CLI、Node 要求和 npm 稳定版兼容性，再将命令写成正式快速开始。`-w` 是 profile 的 workspace 安装选项，不是文件路径。
- 桌面端安装后完整退出并重新打开 DSH；Web 安装后重启对应 Web 宿主，再刷新页面。不能让桌面用户执行 `dsh web` 来重启桌面应用。
- 自定义 profile 用户使用实际 profile 名称；安装到 `web` 不代表 `desktop` 也已安装。
- 不用 npm/pnpm 直接改写已安装的 profile，不猜测桌面端存在的 GUI 安装菜单。
- 固定版本、本地 tarball、注册验证和 pnpm 排错放入指南。未发布的 `@0.5.0` 不能作为可从 npm 下载的示例。
- 如果 README 合并时 0.5.0 仍未发布，在快速开始附近简短注明本文展示主分支的待发布界面、npm 默认安装稳定版；稳定版与当前桌面宿主不兼容时必须说明实际要求。不能用“支持桌面端”掩盖稳定版安装限制。
- 既有兼容性矩阵区分模块契约、浏览器 fixture、完整 Web 与桌面真机；不把某一项通过扩写为所有宿主均已真机验证。
